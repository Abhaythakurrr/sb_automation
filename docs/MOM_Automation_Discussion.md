## Purpose

To discuss automation opportunities within the Stonebranch UAC environment that can reduce manual effort, improve response time to incidents, and streamline job onboarding. Three ideas were proposed and discussed.

## Ideas Proposed

---

### Idea 1 — Bulk Job Creation via REST API

**Problem Statement:**
Currently, creating a new Stonebranch job requires manual entry in the UAC UI — filling in 15+ fields per job across the task and trigger forms. When onboarding multiple jobs at once (which is common during project go-lives), this process is time-consuming and prone to human error.

**Proposed Solution:**
Build an automation that reads job details from a ServiceNow ticket description and automatically creates the corresponding Stonebranch task and its time trigger via the UAC REST API.

**How it would work (concept):**
1. A ServiceNow ticket is raised with job details in a standard format (job name, workstation, script path, schedule, login account, etc.)
2. The automation reads the ticket description
3. It maps the fields to the Stonebranch REST API payload
4. It creates the task and the time trigger in UAC automatically
5. It updates the ServiceNow ticket with the confirmation

**Key parameters the automation would need from the ticket:**
- Job Name
- Job Type (Unix, Windows, SQL, etc.)
- Job Workstation / Agent name
- Script / Command path
- Login Account (credential)
- Schedule (start time, timezone, frequency)
- First Run Date
- Maximum Runtime
- Business Services
- ServiceNow Ticket reference

**Expected benefit:**
- Eliminates manual UAC UI entry for new job requests
- Reduces onboarding time from hours to minutes
- Consistent field mapping — no missed fields

### Idea 2 — Teams Notification with Action Buttons on Agent Offline

**Problem Statement:**
When a Stonebranch agent goes offline, the team currently finds out either by checking UAC manually or after a job failure is reported. There is no proactive notification, and the response requires navigating to UAC to take action.

**Proposed Solution:**
When an agent goes offline, send an automated notification to a Microsoft Teams channel with action buttons that allow the team to respond directly from Teams — without opening UAC.

**Proposed action buttons in the Teams card:**
1. **Suspend Agent** — triggers an API call to suspend the agent in UAC, preventing further job failures from queuing up
2. **Acknowledge / Ignore** — acknowledges the alert and links it to the ServiceNow incident that was auto-generated by UAC's internal integration

**Additional context in the notification:**
- Agent name, host, IP address
- Time the agent went offline
- ServiceNow incident number (auto-generated by UAC) with a direct link to the ticket

**Expected benefit:**
- Team is notified within minutes of an agent going offline
- Response action (suspend or acknowledge) can be taken directly from Teams
- No need to open UAC or ServiceNow separately for initial triage

---

### Idea 3 — Agent Maintenance Mode with Scheduled Time Window

**Problem Statement:**
During OS patching or planned maintenance, agents need to be suspended for a defined time window. Currently this is done manually — someone suspends the agent before the window and resumes it after. If the resume is missed, jobs start failing. Additionally, monitoring alerts fire during the window even though the downtime is planned.

**Proposed Solution:**
Build a maintenance mode feature where the team defines a time window (start time, end time, timezone) for one or more agents. The automation handles the full lifecycle:

1. At the start of the window — agent is automatically suspended in UAC
2. During the window — monitoring alerts for that agent are suppressed (planned downtime, not an incident)
3. At the end of the window — agent is automatically resumed in UAC
4. If the window passes without action (e.g. system restart) — the resume is still executed, the suspend is skipped

**Key inputs needed from the team:**
- Agent name(s)
- Maintenance window start date and time
- Maintenance window end date and time
- Timezone
- Reason / reference (optional, for audit trail)

**Expected benefit:**
- No missed resumes after patching
- No false alerts during planned maintenance
- Full audit trail of maintenance windows
- Team can schedule windows in advance without being online at the exact time

## Points Raised by the Team

- **Job Schedule Tool access** in UAC will need to be provisioned for the service account
- The standard format for ServiceNow job request ticket descriptions should be defined and agreed upon before Idea 1 can be implemented
- The Teams channel and webhook URL for agent notifications needs to be confirmed for Idea 2
